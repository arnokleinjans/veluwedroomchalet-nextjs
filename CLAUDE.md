# Veluwedroomchalet

> **Token-check vóór elke taak:** Beoordeel eerst of de huidige chat al veel context bevat. Als een nieuwe chat token-efficiënter is — meld dat dan **meteen** aan de gebruiker, zonder code te lezen of iets uit te voeren.
>
> Nieuwe chat is slim bij: losse/nieuwe taken, lange conversatiegeschiedenis, wisseling van onderwerp.
> Doorwerken in dezelfde chat is slim bij: directe follow-up op wat net gedaan is.

Next.js web app voor chaletbeheer en gastcommunicatie.

## Stack
- Next.js (App Router), TypeScript, Tailwind CSS
- Dynamische routing: `/b/[bookingId]/` voor per-boeking pagina's
- Chat, info, omgeving, video pagina's per boeking

## Test-database (lokaal)

Lokaal draait de app tegen een TEST-Redis in Docker, nooit tegen productie.
- Starten: `npm run testdb:start` (Docker Desktop moet draaien). Stoppen: `npm run testdb:stop`.
- Verse kopie van productie: `npm run testdb:kopie`. Leest productie met het alleen-lezen-token, wist de TEST-Redis en vult hem opnieuw. Het camping-e-mailadres in TEST wordt `akleinjans@me.com`.
- `.env.local` wijst naar `http://127.0.0.1:8079`. De productiegegevens staan in `.env.productie.local` en zijn alleen voor scripts.
- `getKV()` in `app/utils/db.ts` weigert buiten Vercel elk adres dat niet lokaal is. Zet `vercel env pull` de productie-URL terug in `.env.local`, dan start de app niet.
- Containers en volume heten `TEST-veluwedroomchalet-*`.
- Backups van productie: `antigravity-beheer/redis_backup.py` (menu 12 in beheer.py), opgeslagen in `antigravity-beheer/backups/redis-veluwedroomchalet/`.
- Mediabibliotheek uploaden/verwijderen commit nog steeds naar GitHub `main` en start een Vercel-deploy, ook lokaal.
